The forkable questions that decide the project, and what we actually measured. The full file of truth is docs/TRIALS-E1-E4.md.

E1 — the device is enumerated

A minimal QNX 8.0 image (built with mkifs, no disk, serial console) was booted under QEMU 8.2.2 with -device virtio-gpu-pci. pci-tool -v reports the virtio-gpu modern device at B000:D03:F00:

B000:D03:F00 @ idx 5
	vid/did: 1af4/1050
	class/subclass/reg: 03/80/00

1af4 is the virtio vendor, 1050 the virtio-gpu device id in modern (transitional off) mode, class 03/80/00 = display controller. The virtio-vga variant enumerates too (class 03/00/00). Reproducible via qemu/probe-e1.sh.

E6 — the guest driver really runs

In a real QNX 8.0 guest (a minimal mkifs image booted under QEMU), the Toile guest driver finds the virtio-gpu device, gets an answer to GET_DISPLAY_INFO (scanout 0, 1280×800), gets RESOURCE_CREATE_2D + backing + SET_SCANOUT accepted, and publishes /dev/gpu0:

TOILE: virtio-gpu trouve (1af4/1050) sur B000:D03:F00
toile-gpu: scanout 0 mode 1280x800 (enabled)
toile-gpu: scanout 0 <- resource 1 (1280x800)
TOILE: /dev/gpu0 pret

One defect stays open and is documented rather than hidden: a client opening /dev/gpu0 still crashes inside QNX’s resource-manager library, before any Toile handler runs.

E2, E3, E4 — read the docs

  • E2: the real contract for a third-party Screen display driver in QNX 8.0 is OpenWF Display (WFD) + Wfdcfg, not io-display (a QNX 6.x model absent from the SDP). The guest code is aligned to it and compiles; the integration cannot be tested here because libWFDplatform, wfd-server and libwfdcfg.so ship only in the Screen Board Support package.
  • E3: the Passerelle transport core is reusable; a ~100-line patch covers QNX 8.0 API differences. The transport is adapted, not rewritten.
  • E4: the hypervisor DDK is absent from the installed SDP and not covered by the installed licence — the host-side vdev (side B) stays conditional.

What is not yet measured on target: the real guest→host flush throughput (E5 — the portable core’s own throughput is measured and is ~27 000× above the computed need), the end-to-end vertical sync, and a full Screen desktop in the guest. These are stated plainly in the docs, not papered over.
