Architecture

Three layers

  • Portable core (core/, pure C11): the virtio-gpu 2D command machine — resources, scanouts, backing, flush, transfers — plus the verdict engine and the frozen output formats. It has no clock, no file, no socket, no QNX API and no dynamic allocation.
  • Guest driver (guest/, QNX): PCI enumeration of the virtio-gpu device, transport init (adapted from Passerelle, Apache-2.0), the controlq/cursorq queues, and a resource manager exposing /dev/gpu0.
  • Screen display driver (guest/display/): the QNX Screen display-driver interface on top of the GPU driver — the piece that makes a real QNX desktop appear.

The processing chain

Every virtio-gpu command flows one way, never back:

command  →  parse  →  validate  →  apply to state  →  host effect  →  acknowledge

An invalid command produces a verdict and is never applied partially: the state either changes completely or not at all.

Two implementations, one contract

The core exists twice: in C (core/) and as an independent Python twin (host/). They share only the frozen contract (CONTRACT.md), never code. The differential test (tests/differential.py) replays every fixture through both and compares the output byte for byte — a second independent verification, not a second copy.

Proof strategy

  • P1 coherence — after any valid sequence, the model is consistent (invariants checked after every command).
  • P2 rejection — an invalid command is rejected with a precise verdict, no partial application.
  • P3 determinism — the same sequence produces the same final state and hash, byte for byte.
