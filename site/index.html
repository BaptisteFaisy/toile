Toile

A virtio-gpu 2D driver for QNX 8.0 as a guest (QEMU VM), paired with a Screen display driver. It paints a full QNX desktop in a VM window — with no hardware GPU passthrough. QNX Global Hackathon 2026, Low-level Software.

A QNX developer boots a VM on a laptop and sees a complete QNX desktop in a window — no dedicated card, no passthrough, no second machine.

The problem

A QNX VM boots under QEMU. The kernel comes up, services start… and there is no picture — a serial console only.

Screen, QNX’s graphics server, needs a display driver. QNX ships no virtio-gpu virtual device on the hypervisor side, and no Screen display driver for a virtual GPU in a guest. So in a VM, Screen is unusable without hardware passthrough — which is heavy, hypervisor-specific, non-portable and needs a dedicated card.

What Toile does

Reuse the transport

The hard part of virtio (modern PCI, MSI-X, virtqueues) already exists in the sibling project Passerelle. Toile adapts it and writes only the virtio-gpu layer on top.

Two sides, one risk

Side A (QEMU host) needs only the guest driver and ships first. Side B (QNX Hypervisor host) also needs a host vdev and is conditional on the hypervisor DDK.

A modelable protocol

The virtio-gpu 2D command machine is pure C11: it runs from a unit test on a PC, from a Python twin, and later from the guest driver. The driver is just the glue.

Quick start (no QNX, no QEMU, no GPU needed)

git clone https://github.com/Tradoooo/toile.git
cd toile
make build
make test          # core + Python twin + differential + guards
./build/toile-run run fixtures/boot-graphique.tcl
