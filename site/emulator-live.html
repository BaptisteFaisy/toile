Live guest

A QNX 8.0 guest is really running right now, on the pc host. Inside it, the Toile driver enumerates the virtio-gpu, publishes /dev/gpu0, and a client paints an animated plasma through the device at ~30 frames per second. This page reads that guest live — the screen is re-captured every second, the serial console below is the real boot log.

What you are looking at

  • The moving plasma is painted by an ordinary client inside the guest (guest/common/toile_anim.c): it opens /dev/gpu0, maps the framebuffer, writes pixels, and pushes every frame with TRANSFER_TO_HOST_2D + RESOURCE_FLUSH. QEMU renders it, and this page re-captures it through the QEMU monitor (screendump) once per second.
  • The frame counter (bottom left) and the FPS (bottom right) are drawn by the guest, not by this page: if the guest stopped painting, both would freeze.
  • The console shows the real boot sequence: TOILE: virtio-gpu trouve (1af4/1050), TOILE: /dev/gpu0 pret, CLIENT: /dev/gpu0 ouvert (fd=3), then ANIM: 151 images, 30.2 im/s, present_ko=0.
  • There is no keyboard interaction yet: virtio-input is one of the explicitly-open items — the guest has no input path, so the screen does not react to keys.

Full-screen view with the key-injection console: vitrine Toile. Proofs and procedure in docs/TRIALS-E1-E6.md.
